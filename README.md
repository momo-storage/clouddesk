# CloudDesk

AWS, Microsoft Azure, Google Cloud Platform 가상 서버를 한 화면에서 관리하는 **기업용 CMP(Cloud Management Platform) UI**를 구현한 프론트엔드 포트폴리오입니다.

> **Mock 데이터 기반 데모입니다.** 실제 클라우드 API·백엔드·인증과 연동하지 않으며, 실제 리소스를 제어하지 않습니다. 등록·수정·삭제한 내용은 브라우저 localStorage에만 저장되고, 사용자 메뉴의 "데모 데이터 초기화"로 처음 상태로 되돌릴 수 있습니다.

- 데모: 배포 후 링크 추가 예정
- 저장소: https://github.com/momo-storage/clouddesk

## 개발 목적

- 실제 업무용 B2B 관리 화면에 가까운 정보 밀도와 화면 구성을 React·TypeScript로 구현합니다.
- 데이터 표(정렬·선택·페이지네이션·고정 열), 검색·필터, 등록·수정·삭제 모달, 탭, 차트처럼 업무 화면에서 자주 쓰는 UI를 직접 만든 공통 컴포넌트로 구성합니다.
- 완성형 관리자 템플릿이나 UI 라이브러리 없이 디자인 토큰과 컴포넌트를 직접 설계합니다.

| 리소스 상세           | 개요(기본 정보·현재 사용률·최근 이벤트), 모니터링(CPU·메모리·디스크 차트, 1시간/24시간/7일), 네트워크(VPC·서브넷·IP·인바운드 규칙), 이벤트 로그(심각도 필터) 탭. 탭은 `?tab=`으로 유지, 목록에서 들어온 경우 목록 조건을 유지한 채 복귀 |
| 모니터링              | 실행 중 리소스의 CPU·메모리·디스크 지표와 추이 차트. 제공업체·리소스·기간 필터, 사용률 상위 리소스 목록                                                                                                                                 |
| 비용 관리             | 이번 달 비용·전월 대비, 기간 합계·월평균, 월별 비용 추이, 제공업체별 비중, 서비스 유형별 비용. 제공업체·기간(3/6/12개월) 필터                                                                                                           |
| UI 컴포넌트 가이드    | 화면에서 쓰는 공통 컴포넌트를 분류별로 모은 페이지. 실제 컴포넌트로 상태와 인터랙션을 확인                                                                                                                                              |
| 공통                  | 접을 수 있는 사이드바, 모바일 메뉴 서랍, Breadcrumb, 헤더 알림(읽음 처리), 404·없는 리소스 처리, 데모 데이터 초기화                                                                                                                     |

## 기술 스택

| 구분       | 사용 기술                                 | 선택 이유                                                  |
| ---------- | ----------------------------------------- | ---------------------------------------------------------- |
| 프레임워크 | React 19, TypeScript 6(strict)            | 컴포넌트 단위 설계와 타입 안정성                           |
| 빌드       | Vite 8                                    | 빠른 개발 서버, 라우트 단위 코드 분할                      |
| 라우팅     | React Router 8 (data router, lazy)        | 차트가 있는 화면을 지연 로딩, URL 쿼리로 목록·탭 상태 관리 |
| 스타일     | SCSS + CSS Modules, CSS Custom Properties | 디자인 토큰 관리와 클래스 충돌 방지                        |
| 표         | TanStack Table 9                          | 정렬·페이지네이션·선택 로직만 쓰고 마크업은 직접 구현      |
| 차트       | Recharts 3                                | 선·누적 막대 차트                                          |
| 아이콘     | Lucide React                              |                                                            |
| 품질       | ESLint, Prettier, Playwright              | 정적 검사와 주요 기능 E2E 테스트                           |

서버 상태 관리·전역 상태 라이브러리는 쓰지 않고, React Context + useReducer와 Mock 서비스(지연 Promise + localStorage)로 데이터 흐름을 구성했습니다.

## 구조와 공통 컴포넌트

```
src/
├─ app/          라우터, 라우트 메타(제목·Breadcrumb), Provider
├─ components/
│  ├─ ui/        Button, Input, Select, Checkbox, Radio, Switch, Badge, Tooltip,
│  │             Modal, Dropdown, Tabs, Table, Pagination, Toast, Skeleton, EmptyState
│  ├─ layout/    AppLayout, Header, Sidebar, Breadcrumb, PageHeader, Panel
│  ├─ data/      DataTable, FilterBar, StatCard, StatusBadge, SeverityBadge, UsageBar
│  └─ charts/    MetricChart, CategoryBarChart, ChartDataTable, ChartSkeleton
├─ pages/        dashboard, resources, monitoring, costs, guide, not-found
├─ services/     Mock 서비스(300~600ms 지연 Promise + localStorage), 집계 함수
├─ store/        데모 데이터 Context(useReducer), Toast
├─ mocks/        결정적 시드 데이터(리소스 80, 이벤트, 비용 12개월, 시계열 계산)
├─ styles/       디자인 토큰(SCSS 맵 → CSS Custom Properties), Mixin
└─ types, constants, hooks, utils
```

- **공통 컴포넌트:** 두 화면 이상에서 쓰는 것만 `components/`에 두고, 한 화면 전용 컴포넌트는 `pages/*/components`에 둡니다.
- **DataTable:** TanStack Table 위에 직접 만든 표 기본 요소(Table)·Pagination·Checkbox를 조합했습니다. 정렬·페이지·선택 상태를 사용처가 제어해 URL 쿼리와 동기화하기 쉽게 했습니다.
- **차트:** 모든 차트에 요약 문장과 "데이터 표로 보기"를 함께 둡니다.
- **데이터 흐름:** 화면은 Context의 상태만 읽고, 변경은 서비스 함수(저장소 반영) → reducer 순서로만 합니다. 그래서 목록·상세·대시보드·알림이 같은 데이터를 봅니다.
- **Mock 데이터:** 기준 시각(2026-11-26 09:00 KST)과 시드를 고정해 새로고침해도 같은 데이터가 나옵니다.

## AI 활용 개발 과정

Anthropic의 Claude(Claude Code)를 개발 도구로 사용했습니다. 요구사항과 판단은 직접 정하고, AI는 설계 초안·코드 작성·검증 실행을 맡겼습니다. 모든 단계는 결과를 검토하고 승인한 뒤 다음 단계로 진행했습니다.

1. **요구사항 정의와 범위 설정:** 화면·기능·기술 스택·디자인 방향을 지침으로 정리하고, 1차(대시보드·리소스·가이드)와 2차(모니터링·비용) 범위로 나눴습니다. 진행 중에 포트폴리오 목적에 맞게 범위를 조정했습니다(사용자 관리 화면 제외, 접근성 검증 범위 축소).
2. **기술 스택 선정과 설계 검토:** AI가 작성한 설계서 초안(디렉터리 구조, 공통 컴포넌트 목록, 디자인 토큰, 화면별 기능)을 검토해 수정 사항을 반영하고 확정했습니다.
3. **AI를 활용한 코드 구현:** 단계(Phase)별로 구현을 지시하고, 결과 화면을 캡처로 받아 확인했습니다.
4. **구현 결과 검토와 개선:** 화면을 보고 개선을 요청했습니다. 예: 리소스 목록 행 높이·정보 밀도 조정, PC 고정 열, 상세 개요의 사용률 그래프 형태, 목록 복귀 시 조회 조건 유지.
5. **단계별 품질 검증과 Git 관리:** 단계마다 타입 검사·린트·빌드·E2E를 실행하고 결과를 확인한 뒤 커밋했습니다. 커밋 작성자 정보와 민감 정보를 점검하고 공개 저장소에 올렸습니다.

## 로컬 실행

요구 환경: Node.js 26(`.nvmrc`, 26.13.1에서 확인), npm 11 이상

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # 타입 검사 후 dist/에 빌드
npm run preview    # 빌드 결과 확인: http://localhost:4173
```

| 명령                     | 설명                                                 |
| ------------------------ | ---------------------------------------------------- |
| `npm run typecheck`      | TypeScript 타입 검사                                 |
| `npm run lint`           | ESLint                                               |
| `npm run format:check`   | Prettier 서식 검사(`npm run format`은 정리)          |
| `npm run check:data`     | Mock 데이터 규칙과 데이터 서비스 등록·수정·삭제 검사 |
| `npm run test:e2e`       | Playwright 주요 기능·반응형 테스트(Chromium)         |
| `npm run test:e2e:a11y`  | (선택) 기능 테스트 + axe 자동 접근성 검사            |
| `npm run check:contrast` | (선택) 색상 토큰 명도 대비 계산                      |

E2E 테스트를 처음 실행할 때는 `npx playwright install chromium`으로 브라우저를 설치합니다.

**검증 범위와 한계**

- Chrome(Chromium)에서만 확인했습니다. Firefox·Safari·Edge 개별 검증은 하지 않았습니다.
- 접근성은 기본 웹 표준 수준(시맨틱 마크업, 입력 서식 레이블, 키보드 조작, 초점 표시)으로 적용했습니다. 화면 낭독기 수동 검증, 고대비 모드, 400% 확대 검증은 하지 않았으며, 접근성 표준을 모두 준수한다고 확인한 것은 아닙니다.
- axe 자동 검사와 명도 대비 계산은 선택 실행 스크립트로 남겨 두었습니다.
